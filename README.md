# vulnscan

Automated low-level vulnerability scanner for ELF binaries (Linux x86-64).

Detects **6 vulnerability classes** via combined static and dynamic analysis:

| Class | CWE | Detection |
|-------|-----|-----------|
| Stack buffer overflow | CWE-121 | Static (disasm + taint) + Dynamic (fuzzer + GDB triage) |
| Heap buffer overflow | CWE-122 | Static (frame analysis) + Dynamic (fuzzer) |
| Format string | CWE-134 | Static (dangerous func + taint) + Dynamic (fuzzer) |
| Integer overflow | CWE-190 | Static (consequence: heap BOF) + Dynamic (boundary fuzzing) |
| Use-after-free | CWE-416 | Static (limited: intra-procedural only) |
| Off-by-one | CWE-193 | Static (limited: intra-procedural only) |

> **Security note:** Dynamic analysis executes potentially hostile binaries.
> Run in a VM or container. Resource limits (`RLIMIT_AS`, `RLIMIT_CPU`) are
> applied automatically, but isolation is not a substitute for sandboxing.

## Requirements

### System
```bash
sudo apt install gcc gdb make
```

### Python (3.10+)
```bash
# Create virtual environment and install dependencies
python3 -m virtualenv .venv
source .venv/bin/activate
pip install -r requirements.txt -e .
```

Or with pip directly:
```bash
pip install -e .
```

## Build the corpus

The corpus contains 6 intentionally vulnerable C programs, each compiled in two
variants: `_normal` (default protections), `_vuln` (all protections disabled).

```bash
make -C corpus all      # all variants
make -C corpus vuln     # only _vuln builds (scanner target)
```

Binaries land in `corpus/bin/`.

## Usage

```bash
# Full scan (static + dynamic), JSON + HTML report
vulnscan scan corpus/bin/stack_bof_vuln --html --out reports/stack_bof.json

# Static analysis only (fast, no binary execution)
vulnscan scan corpus/bin/heap_bof_vuln --no-dynamic

# Dynamic analysis only
vulnscan scan corpus/bin/format_string_vuln --no-static

# Longer timeout for complex binaries
vulnscan scan corpus/bin/integer_overflow_vuln --timeout 60 --html

# Verify system dependencies
vulnscan check-deps
```

### Output

**JSON** (`--out FILE`): machine-readable report with all findings, protections,
and summary counts.

**HTML** (`--html`): self-contained dark-theme report with:
- Severity summary cards (CRITICAL / HIGH / MEDIUM / LOW / INFO)
- Protection matrix (NX, Canary, RELRO, PIE, Fortify, RPATH)
- Findings table sorted by severity with evidence, CWE, confidence

**Terminal**: text summary printed after every scan.

## Demo

```bash
./run.sh
```

Builds the full corpus, scans all 6 `_vuln` binaries with both static and dynamic
analysis, writes JSON + HTML reports to `reports/`. Accepts `--no-dynamic` and
`--timeout N`.

## Architecture

```
vulnscan/
├── cli.py                # argparse entry point (scan, check-deps)
├── pipeline.py           # orchestration: static → dynamic → merge → report
├── static/
│   ├── elf_info.py       # ELF parsing, PLT map (lief 1.0 + capstone)
│   ├── protections.py    # NX, canary, RELRO, PIE, fortify, rpath detection
│   ├── dangerous_funcs.py# 17 dangerous function call sites (CALL → PLT)
│   ├── disasm.py         # frame analysis: buffer size vs argument length
│   └── taint.py          # intra-procedural taint: sources → sinks
├── dynamic/
│   ├── runner.py         # safe subprocess executor (RLIMIT_AS/CPU/CORE)
│   ├── fuzzer.py         # 5 strategies: size, cyclic, format, int-boundary
│   └── triage.py         # GDB batch triage, RIP offset, severity engine
├── report/
│   ├── model.py          # dataclasses: Finding, Protection, ScanResult
│   ├── generator.py      # render_json(), render_html(), save()
│   └── templates/
│       └── report.html.j2# Jinja2 dark-theme HTML template
└── utils/
    ├── logging.py        # structured logging, silences pwnlib/lief noise
    └── shell.py          # secure subprocess wrapper, dep checker
corpus/
├── src/                  # 6 C source files with documented vulnerabilities
├── bin/                  # compiled binaries (generated by make)
└── Makefile
docs/
├── methodologie.md       # pipeline architecture and detection methods
├── algorithmes.md        # non-trivial algorithm details
├── resultats.md          # real scan results on the corpus
└── limites.md            # known limitations and false-positive patterns
tests/
├── test_phase0.py        # CLI, shell wrapper, data model
├── test_phase1_corpus.py # corpus binaries, crash detection
├── test_phase2_static.py # ELFInfo, protections, dangerous funcs
├── test_phase3_advanced.py# disasm, taint, pipeline
├── test_phase4_dynamic.py # runner, fuzzer, pipeline dynamic
├── test_phase5_triage.py  # GDB triage, severity engine
└── test_phase6_report.py  # JSON/HTML generation, CLI output
```

## Detection pipeline summary

```
ELF binary
 │
 ├─► ELF parse (lief 1.0)        arch, sections, PLT map
 ├─► Protections                  NX/Canary/RELRO/PIE/Fortify
 ├─► Dangerous functions          CALL sites → PLT stubs
 ├─► Frame analysis               buffer size vs read length
 ├─► Taint tracking               gets/read → strcpy/printf/system
 │
 ├─► Fuzzer (5 strategies)        cyclic, size escalation, %n, int-boundary
 └─► GDB triage                   RIP value, offset, exploitability
      │
      └─► Merge findings          static + dynamic → confidence="both"
           └─► Severity engine    class × exploitability × offset × protections
```
